# Исследовательский вопрос и гипотезы (зафиксированы до запуска основного эксперимента)

Дата фиксации: 2026-10-06. Документ записан до запуска `src/run_experiment.py`: на этот момент
были извлечены признаки и размечены говорящие, но ни одна модель ещё не обучалась. Изменения
после получения результатов вносятся только в раздел «Отклонения от плана» в конце файла,
с указанием причины.

## Исследовательский вопрос

Насколько на датасете Real-life Trial (121 клип, 56 говорящих) оценка качества распознавания
обмана по лицевой динамике (blendshape-коэффициенты и поза головы MediaPipe) зависит:
- от протокола разбиения — по клипам, по говорящим или по судебным делам;
- от способа временного моделирования — порядко-инвариантные статистики, BiGRU или
  Transformer-энкодер.

Отдельно проверяется, даёт ли временной порядок кадров какую-либо информацию сверх
распределения покадровых признаков.

## Гипотезы

- **H1 (утечка через личность).** При стратифицированном 10-fold по клипам ROC AUC и точность
  выше, чем при разбиении по говорящим. Разность ΔAUC(clip − speaker) положительна, её
  95 % ДИ (кластерный бутстрэп по говорящим) не включает 0 хотя бы для части моделей.
- **H2 (механизм).** Признаки несут информацию о личности: точность 1-NN идентификации
  говорящего по статистическим дескрипторам мимики и позы намного выше случайной. Модель
  `identity_1nn` (метка клипа с ближайшим дескриптором лица SFace, без поведенческих признаков)
  при разбиении по клипам даёт качество существенно выше 0,5. При разбиении по говорящим её
  качество падает до уровня случайного или ниже.
- **H3 (временное моделирование).** При разбиении по говорящим и по делам ни Transformer, ни
  BiGRU не превосходят порядко-инвариантные базовые модели (логистическая регрессия на
  статистиках, MLP с усреднением по времени) статистически значимо: 95 % ДИ разности AUC
  включает 0.
- **H4 (роль порядка кадров).** Перемешивание порядка кадров не ухудшает качество
  Transformer статистически значимо (ДИ ΔAUC включает 0).
- **H5 (короткие пути записи).** Технические параметры видео (разрешение, fps, длительность,
  битрейт) связаны с меткой. Классификатор только по ним даёт AUC выше 0,5 при разбиении
  по клипам.

## Критерии

- Основная метрика — ROC AUC, дополнительные — accuracy и balanced accuracy (порог 0,5).
- Интервалы: 95 % перцентильный кластерный бутстрэп по говорящим, B = 1000. Метрика на
  каждой бутстрэп-выборке усредняется по 5 повторам кросс-валидации.
- Подтверждение гипотезы о различии — 95 % ДИ разности не включает 0. Гипотеза об
  отсутствии различия (H3, H4) формулируется осторожно: «различие не обнаружено при данной
  мощности», а не «модели эквивалентны».
- Все гиперпараметры зафиксированы в `configs/experiment.yaml` до запуска. Подбор по тестовым
  фолдам не выполняется. Параметр C логистической регрессии выбирается внутренней
  кросс-валидацией того же типа, что и внешняя.

## Отклонения от плана


1. **Добавлена диагностическая модель `prior` и метрика `auc_fold` (AUC внутри фолдов, усреднённый).**
   - Причина. При первом запуске (2026-10-06, `logs/run_experiment.log`) объединённый (pooled)
     AUC нейросетевых моделей при групповых разбиениях оказался ниже 0,5. Модель `prior`
     (предсказание = доля обманных клипов в обучающей части фолда) была добавлена после
     первого запуска. При разбиении по говорящим она даёт pooled AUC ≈ 0,34, что подтверждает
     артефакт сдвига априорной доли классов между фолдами.
   - Первая попытка коррекции. Пробовалась поправка `logit(p) − logit(π_train)` (Saerens et al.,
     2002; метрики `*_pc`). От неё отказались, не используя в выводах: для моделей с
     дискретными или равными выходами (`identity_1nn`) поправка сама вносит в ранжирование
     информацию об обратной априорной доле и завышает AUC (0,60 вместо ≈0,5 у 1-NN при
     разбиении по говорящим).
   - Итоговое решение. Как устойчивая к межфолдовой калибровке метрика используется
     `auc_fold`: AUC внутри каждого тестового фолда с обоими классами, усреднённый по фолдам.
     Объединённый AUC по-прежнему сообщается как метрика, заданная планом.
   - Что не менялось. Гиперпараметры и предсказания остальных моделей.
2. Модель `identity_1nn` использует дескриптор лица SFace (этап извлечения признаков), а не
   форму лица по ключевым точкам. Форма лица оставлена в аудите идентифицируемости
   (`results/audit/audit.json`). Решение принято до запуска моделей.
3. **Разведочный аудит `gender`, добавлен после первого запуска.** Предсказание — доля обманных
   клипов среди клипов того же пола в обучающей части. Цель — сопоставить качество лицевых
   моделей с известным демографическим смещением RLT (Mambreyan et al., 2022). Пол размечен
   по видео при разметке говорящих: 21 женщина и 35 мужчин, что совпадает с README датасета.
4. **Разведочная декомпозиция AUC на пары внутри одного говорящего и между говорящими**
   (`src/pair_analysis.py`). Не планировалась. Используется только для интерпретации.
5. **Проверка устойчивости: ранняя остановка нейросетей (`framepool_es`, `gru_es`, `transformer_es`),
   добавлена 2026-10-12 после первого запуска.**
   - Причина. AUC нейросетевых моделей при групповых разбиениях оказался ниже 0,5 (у MLP ДИ не
     включает 0,5). Нужно проверить, не объясняется ли это переобучением при фиксированных
     40 эпохах, а не свойствами данных.
   - Процедура. Архитектуры и все остальные гиперпараметры не меняются. Внутри обучающей части
     каждого внешнего фолда выделяется валидационная часть — первый фолд внутреннего 5-кратного
     разбиения того же типа, что и внешнее (по клипам / говорящим / делам). Модель обучается до
     40 эпох; выбирается эпоха с минимальной BCE на валидации. Затем модель заново обучается на
     всей обучающей части выбранное число эпох. Тестовый фолд в выборе не участвует.
   - Статус. Разведочный анализ; гипотезы H1–H5 и их проверка на исходных моделях не меняются.
     Предсказания исходных моделей после рефакторинга `src/models.py` воспроизводятся бит в бит.
6. **Отчётность по фолдам.** `auc_fold` усредняет AUC по тестовым фолдам с клипами обоих классов.
   Добавлен отчёт `results/aggregate/fold_summary.csv`: во всех протоколах и повторах все 10 фолдов
   содержат оба класса, т. е. ни один фолд из усреднения не исключался.
