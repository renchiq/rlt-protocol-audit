# Данные и протоколы разбиения

## Корпус

**Real-life Trial Deception Detection Dataset, версия 1.0 (январь 2016).**

- Ссылка на корпус: Pérez-Rosas V., Abouelenien M., Mihalcea R., Burzo M. Deception detection
  using real-life trial data. ICMI 2015, pp. 59–66. doi:10.1145/2818346.2820758.
- Архив: `https://web.eecs.umich.edu/~mihalcea/downloads/RealLifeDeceptionDetection.2016.zip`
  (SHA-256 — в `checksums.sha256`).
- Состав: 121 видеоклип, 61 обманный (`trial_lie_*`) и 60 правдивых (`trial_truth_*`).
  Метка определяется вердиктом суда (guilty / not guilty) или фактом реабилитации (exoneration).
- В архив входят также транскрипты и ручная разметка жестов по схеме MUMIN: 39 бинарных
  признаков, файл `Annotation/All_Gestures_Deceptive and Truthful.csv`.
- Видео в репозиторий не включаются (каталог `data/` исключён из git). Их нужно скачать
  с сайта авторов, см. `run_all.sh`.

Особенности, важные для оценки:

- Официальных идентификаторов говорящих нет. В README корпуса указано 56 уникальных говорящих
  (21 женщина и 35 мужчин), но соответствие «клип → говорящий» не дано.
- В таблице README строка `trial_truth_008` повторена дважды, а `trial_truth_009`
  отсутствует. Вторая запись отнесена к `trial_truth_009`: та же роль и то же дело
  (`src/build_metadata.py`).
- Клипы неоднородны по источнику, разрешению (23 значения), частоте кадров и качеству.

## Разметка говорящих (`metadata/speaker_annotation.csv`)

Разметка выполнена полуавтоматически:

1. **Детекция лиц и дескрипторы** (`src/detect_faces.py`). На каждом кадре (10 кадров/с)
   работают детектор YuNet и дескриптор SFace (OpenCV Zoo). Лица клипа жадно
   кластеризуются по косинусной близости (порог 0,363). Для каждого кластера-кандидата
   сохраняется миниатюра.
2. **Выбор целевого лица.** По умолчанию берётся кандидат с наибольшим рангом
   (число кадров × уверенность детектора × размер лица). Все 121 клип проверены визуально
   по листам кандидатов (`tools/candidate_sheets.py`). В 3 клипах выбор исправлен вручную
   (`metadata/target_face.csv`): в кадре находились адвокат или второе лицо на разделённом
   экране.
3. **Объединение клипов в говорящих.** Используется косинусная близость дескрипторов
   выбранных лиц (для одного человека, как правило, > 0,7) с визуальной проверкой
   контрольных кропов (`tools/contact_sheets.py`). Один случай (`trial_lie_050`, размытая
   запись допроса) объединён с `trial_lie_036` по описанию в README (Defendant / Marissa
   Devault). Комментарии к спорным случаям — в столбце `note`.
4. **Пол** определён визуально.

Итог: 56 говорящих (21 женщина и 35 мужчин), что совпадает с README корпуса. Сводка
(`results/audit/audit.json`):

| Показатель | Значение |
|---|---|
| Говорящих | 56 |
| Говорящих с одним клипом | 41 |
| Максимум клипов у одного говорящего | 21 |
| Клипов у 4 самых представленных говорящих | 50 |
| Говорящих с клипами обоих классов | 5 (50 клипов) |
| Доля обманных клипов: женщины / мужчины | 65,3 % (75 клипов) / 26,1 % (46 клипов) |

Идентификаторы `S01`–`S56` условные. Имена людей в разметке не используются, а поле
`case_group` берётся из README корпуса.

## Группы «дело» (`case_id`)

Это поле «trial name» из README корпуса после символа `/`: 32 группы. Все участники одного
процесса (подсудимый, свидетели, адвокат) образуют одну группу. Интервью
реабилитированных — отдельные группы (по одной на человека). Два клипа юристов Innocence
Project объединены в одну группу.

## Протоколы разбиения (`src/splits.py`, `splits/*.json`)

| Протокол | Реализация | Что исключает |
|---|---|---|
| `clip` | `StratifiedKFold(10, shuffle=True)` | ничего (базовая практика ранних работ) |
| `speaker` | `StratifiedGroupKFold(10, shuffle=True)`, группа — `speaker_id` | перекрытие говорящих между обучением и тестом |
| `case` | `StratifiedGroupKFold(10, shuffle=True)`, группа — `case_id` | перекрытие говорящих **и** судебных дел: общая обстановка, камера, тема |

- Для каждого протокола используются 5 зёрен (`seeds: [0..4]`). Разбиения сохранены в
  `splits/<protocol>_seed<k>.json`.
- `splits/summary.csv` показывает число групп, попадающих в несколько блоков. Для `speaker`
  это 0 говорящих, для `case` — 0 говорящих и 0 дел. Для `clip` в среднем 14,4 говорящего
  и 17,8 дела разделены между блоками, то есть subject leakage присутствует по построению.
- Внутренняя кросс-валидация для подбора C логистической регрессии использует тот же тип
  разбиения, что и внешняя: 5 блоков, группы — внутри обучающей части.

## Почему разбиение по говорящим недостаточно

Аудит (`results/audit/audit.json`, `src/audit.py`) показывает, что технические параметры
записи связаны с меткой:

- критерий χ² для таблицы «разрешение × метка»: p ≈ 1,5·10⁻⁵;
- частота кадров у разных классов различается: p ≈ 4,3·10⁻⁶.

Случайный лес только по разрешению, частоте кадров, длительности и битрейту даёт
AUC (внутри блоков) 0,74 при разбиении по говорящим и 0,69 при разбиении по делам. Поэтому
разбиение `case` — минимально необходимое, а результаты по всем протоколам следует
сопоставлять с аудиторскими моделями.
